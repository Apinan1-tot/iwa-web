# IWA RICH YOU D — เว็บไซต์ + ระบบแอดมินหลังบ้าน

## 🆕 อัปเดตล่าสุด
- **แก้ปัญหาติดตั้งไม่ได้บน Windows** — เปลี่ยนจาก `better-sqlite3` (ต้องคอมไพล์) เป็น `node:sqlite` ที่ติดมากับ Node.js อยู่แล้ว **ไม่ต้องคอมไพล์อะไรอีกต่อไป** (ต้องใช้ Node.js เวอร์ชัน 22.5 ขึ้นไป)
- **หมวดหมู่ซ่อน/แสดงได้แล้ว** — เหมือนสินค้า มีปุ่มสลับสถานะในหน้าแอดมิน → หมวดหมู่
- **หมวดหมู่ใหม่ใช้งานได้ทันที** — ไม่ต้องรอสร้างไฟล์ HTML เพิ่มอีกต่อไป ระบบมีหน้าเว็บกลาง (`products/category.html?slug=...`) ที่รองรับหมวดหมู่ทุกอันอัตโนมัติ
- **มีลิงก์เข้าแอดมินที่หน้าเว็บจริงแล้ว** — ลิงก์เล็กๆ "ระบบจัดการ" ท้ายหน้า (ผ่าน `assets/js/motion.js`)
- **เมนูด้านซ้ายของแอดมินค้างอยู่กับที่เวลาเลื่อนหน้าจอ** (sticky sidebar)
- ฐานข้อมูลจะ**อัปเกรดตัวเองอัตโนมัติ**ตอนสตาร์ทเซิร์ฟเวอร์ครั้งแรกหลังอัปเดต ไม่ลบข้อมูลเดิม


ระบบนี้ประกอบด้วย 2 ส่วน ทำงานร่วมกันผ่านฐานข้อมูลเดียวกัน:

1. **เว็บไซต์หน้าบ้าน** (`public/`) — หน้ารวมสินค้า หน้าหมวดหมู่ หน้ารายละเอียดสินค้า ดึงข้อมูลจากฐานข้อมูลแบบสด (real-time)
2. **ระบบแอดมินหลังบ้าน** (`/admin`) — เพิ่ม/แก้ไข/ลบสินค้า จัดการหมวดหมู่ อัปโหลดรูปภาพ

**เมื่อแก้ไขข้อมูลในหน้าแอดมิน → คนที่เข้าเว็บไซต์จะเห็นการเปลี่ยนแปลงทันที** ไม่ต้องแก้โค้ดหรืออัปโหลดไฟล์ใหม่

## 1. โครงสร้างไฟล์

```
IWA-main/                  ← โฟลเดอร์หลักของเว็บไซต์ (repo เดิมของคุณ)
├── server/               ← โค้ด backend (Node.js + Express) — โฟลเดอร์ใหม่
│   ├── server.js         ← จุดเริ่มต้นของเซิร์ฟเวอร์
│   ├── db/
│   │   ├── database.js   ← สร้างตารางฐานข้อมูล (SQLite)
│   │   └── seed.js       ← ใส่ข้อมูลสินค้าเริ่มต้น + สร้างบัญชีแอดมิน
│   ├── routes/            ← API ทั้งหมด
│   └── middleware/        ← ระบบล็อกอิน + อัปโหลดรูป
├── admin/                 ← หน้าเว็บของระบบแอดมิน — โฟลเดอร์ใหม่
├── assets/                ← ของเดิมที่คุณมีอยู่แล้ว (css/js/img) — เพิ่มไฟล์ js ใหม่ 2 ไฟล์เข้าไป
├── products/              ← ของเดิมที่คุณมีอยู่แล้ว — บางไฟล์ถูกแทนที่ด้วยเวอร์ชัน dynamic
├── uploads/               ← โฟลเดอร์ใหม่ — รูปที่แอดมินอัปโหลดจะถูกเก็บที่นี่
├── data/                  ← โฟลเดอร์ใหม่ — ฐานข้อมูล SQLite (สร้างอัตโนมัติตอนรันครั้งแรก)
├── index.html             ← ของเดิมที่คุณมีอยู่แล้ว (ไม่ต้องแก้ไข)
├── package.json           ← ไฟล์ใหม่
└── .env.example           ← ไฟล์ใหม่ (คัดลอกเป็น .env)
```

**ไฟล์ `index.EXAMPLE-homepage.html`** ในแพ็กเกจนี้เป็นแค่ตัวอย่างหน้าแรกสำรอง (เผื่อไม่มีของเดิม) — **ไม่ต้องใช้** เพราะคุณมี `index.html` จริงอยู่แล้ว ลบทิ้งได้เลย

## 2. วิธีรันทดสอบในเครื่องตัวเอง

ต้องมี [Node.js](https://nodejs.org) เวอร์ชัน **22.5 ขึ้นไป** ติดตั้งในเครื่องก่อน (แนะนำเวอร์ชัน LTS ล่าสุด) — เช็คเวอร์ชันด้วย `node -v`

```bash
# 1) ติดตั้งไลบรารีที่จำเป็น
npm install

# 2) สร้างฐานข้อมูล + ใส่ข้อมูลสินค้าเริ่มต้น (รันครั้งเดียวตอนเริ่มต้น)
npm run seed

# 3) เริ่มเซิร์ฟเวอร์
npm start
```

จากนั้นเปิดเบราว์เซอร์:
- เว็บไซต์หน้าบ้าน: **http://localhost:3000/**
- ระบบแอดมิน: **http://localhost:3000/admin**

**บัญชีแอดมินเริ่มต้น** (สร้างจากคำสั่ง `npm run seed`):
- ชื่อผู้ใช้: `admin`
- รหัสผ่าน: `ChangeMe123!`

⚠️ **สำคัญมาก:** หลังล็อกอินครั้งแรก ให้ไปที่เมนู "บัญชีผู้ใช้" ในแอดมินแล้วเปลี่ยนรหัสผ่านทันที ก่อนเปิดให้คนอื่นเข้าเว็บได้

## 3. วิธีใช้งานระบบแอดมิน

### เพิ่มสินค้าใหม่
1. เข้า `/admin` → ล็อกอิน → เมนู "สินค้า" → กด "+ เพิ่มสินค้าใหม่"
2. อัปโหลดรูปภาพหลัก (ระบบจะย่อขนาดให้อัตโนมัติ ไม่ต้องแก้ไขรูปเอง)
3. เลือกหมวดหมู่ กรอกชื่อ คำอธิบายสั้น รายละเอียดเต็ม
4. กด "บันทึกสินค้า" → สินค้าจะขึ้นบนเว็บไซต์ทันที

### แก้ไข / ซ่อน / ลบสินค้า
- หน้า "สินค้า" มีปุ่มแก้ไขและลบในแต่ละแถว
- กดที่ป้ายสถานะ ("แสดงผล"/"ซ่อนอยู่") เพื่อสลับการแสดงผลโดยไม่ต้องลบข้อมูล

### จัดการหมวดหมู่
- เมนู "หมวดหมู่" → เพิ่ม/แก้ไข/ลบหมวดหมู่ได้
- **หมายเหตุ:** หมวดหมู่ใหม่ที่เพิ่มจะขึ้นในหน้ารวมสินค้า (`/products/`) โดยอัตโนมัติ แต่หน้าโชว์สินค้าของหมวดนั้น (เช่น `/products/ชื่อหมวด.html`) ต้องสร้างไฟล์ HTML เพิ่มเอง (คัดลอกจากหน้าหมวดหมู่ที่มีอยู่แล้วปรับ `data-category` ให้ตรงกับ slug ของหมวดใหม่) — หากต้องการให้ผมช่วยสร้างหน้าใหม่ให้ครบ แจ้งชื่อหมวดที่ต้องการเพิ่มได้เลย

## 4. การ Deploy ขึ้นเซิร์ฟเวอร์จริง

เนื่องจากเว็บนี้ต้องมี backend (Node.js) รันตลอดเวลา **โฮสต์แบบ static (เช่น GitHub Pages) จะใช้ไม่ได้** ต้องเลือกโฮสต์ที่รองรับ Node.js

### ตัวเลือกแนะนำ (ใช้งานง่าย เหมาะกับเว็บขนาดนี้)

#### วิธีที่ 1: Railway.app (แนะนำที่สุดสำหรับมือใหม่)
1. สมัครบัญชีที่ [railway.app](https://railway.app) (ล็อกอินด้วย GitHub ได้)
2. สร้างโปรเจกต์ใหม่ → "Deploy from GitHub repo" (ต้อง push โค้ดนี้ขึ้น GitHub ก่อน) หรือใช้ Railway CLI อัปโหลดโดยตรง
3. ตั้งค่า Environment Variables ในหน้า Railway:
   - `SESSION_SECRET` = ข้อความสุ่มยาวๆ (ห้ามใช้ค่าตัวอย่าง)
   - `NODE_ENV` = `production`
4. Railway จะรันคำสั่ง `npm install` และ `npm start` ให้อัตโนมัติ
5. หลัง deploy เสร็จ ให้เปิด **Shell/Console ของ Railway** แล้วรัน `npm run seed` ครั้งเดียวเพื่อสร้างฐานข้อมูลเริ่มต้น
6. ต่อโดเมนของตัวเอง (Custom Domain) ได้ในหน้าตั้งค่าโปรเจกต์

#### วิธีที่ 2: Render.com
1. สมัครบัญชีที่ [render.com](https://render.com)
2. สร้าง "Web Service" ใหม่ เชื่อมกับ GitHub repo ของโค้ดนี้
3. ตั้งค่า:
   - Build Command: `npm install`
   - Start Command: `npm start`
   - เพิ่ม Environment Variable `SESSION_SECRET` และ `NODE_ENV=production`
4. **สำคัญ:** เพิ่ม "Persistent Disk" (Render มีให้ฟรีบางส่วน) แล้ว mount ไปที่โฟลเดอร์ `data/` และ `public/uploads/` ไม่เช่นนั้นข้อมูลสินค้าและรูปจะหายทุกครั้งที่ระบบ restart/redeploy
5. รัน `npm run seed` ผ่าน Render Shell หนึ่งครั้งหลัง deploy

#### วิธีที่ 3: VPS ธรรมดา (DigitalOcean, Vultr, หรือเครื่องของบริษัทเอง)
ถ้ามี VPS อยู่แล้วหรือกำลังจะเช่า:
```bash
# ติดตั้ง Node.js บนเซิร์ฟเวอร์ (Ubuntu ตัวอย่าง)
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt install -y nodejs

# อัปโหลดโค้ดขึ้นเซิร์ฟเวอร์ แล้ว
npm install --production
npm run seed
npm install -g pm2      # ตัวช่วยรันเซิร์ฟเวอร์ให้ทำงานตลอด ไม่ดับเมื่อปิด terminal
pm2 start server/server.js --name iwa-site
pm2 save
pm2 startup             # ตั้งให้รันอัตโนมัติเมื่อเซิร์ฟเวอร์รีสตาร์ท
```
จากนั้นตั้งค่า **Nginx** เป็น reverse proxy ชี้มาที่ port 3000 และติดตั้ง SSL ฟรีด้วย **Certbot** (จำเป็นมาก เพื่อให้ระบบ login ปลอดภัย)

### ⚠️ ข้อควรระวังสำคัญก่อนเปิดใช้งานจริง
1. **เปลี่ยนรหัสผ่านแอดมินทันที** จาก `ChangeMe123!` เป็นรหัสผ่านที่คาดเดายาก
2. **ตั้งค่า `SESSION_SECRET`** เป็นข้อความสุ่มที่ไม่ซ้ำกับค่าตัวอย่างในโค้ด
3. **ต้องใช้ HTTPS เสมอ** ในการใช้งานจริง (โฮสต์ส่วนใหญ่อย่าง Railway/Render มี HTTPS ให้อัตโนมัติ)
4. โฟลเดอร์ `data/` (ฐานข้อมูล) และ `public/uploads/` (รูปภาพ) **ต้องมีการสำรองข้อมูล (backup)** สม่ำเสมอ เพราะเป็นที่เก็บข้อมูลสินค้าทั้งหมด

## 5. การสำรองข้อมูล (Backup)

ฐานข้อมูลทั้งหมดอยู่ในไฟล์เดียว: `data/site.db`
วิธีสำรองง่ายที่สุดคือคัดลอกไฟล์นี้ (และโฟลเดอร์ `public/uploads/`) เก็บไว้เป็นระยะ เช่น ทุกสัปดาห์

```bash
# ตัวอย่างคำสั่งสำรองข้อมูล
cp data/site.db backup/site-$(date +%Y%m%d).db
tar -czf backup/uploads-$(date +%Y%m%d).tar.gz public/uploads/
```

## 6. หมายเหตุเรื่องหมวดหมู่ที่มีดีไซน์พิเศษ

หน้า `iwa-smart-board.html` (Iwa AiBoard) ยังคงหน้าเอกสารสินค้าและ Specification แบบเดิม (`aiboard-document.html`, `aiboard-specification.html`) ไว้ตามดีไซน์เดิม เพราะเป็นเนื้อหาข้อมูลจำเพาะ (ไม่ใช่รายการสินค้าที่ CRUD ได้) — ส่วนรุ่นสินค้า (65″/75″/86″) จัดการผ่านระบบแอดมินได้ตามปกติ

หากในอนาคตต้องการเพิ่มหมวดหมู่ใหม่ที่มีดีไซน์เฉพาะของตัวเอง (ไม่ใช่การ์ดสินค้าธรรมดา) จะต้องสร้างไฟล์ HTML เพิ่มเติม — สามารถแจ้งรายละเอียดมาได้ ผมช่วยสร้างให้ได้เพิ่มเติม
